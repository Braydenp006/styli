## Phase 3: how it is built and what limits it

Kotlin is in `android/app/src/main/kotlin/app/styli/ink/`, tests in `android/app/src/test/kotlin/app/styli/ink/`. `PageModel` (plain Kotlin) holds one page, its undo steps and, in `log`, the events that are the ink log; `Notebook` holds the pages (grid cells, page undo, picture bytes); `InkCanvasView` does touch, drawing and the lasso; `MainActivity` has the throwaway toolbar. Pure maths is in small files tested on the JVM: `PageGeometry`, `NotebookLayout`, `LassoGeometry`, `Chart.kt` (`ChartMaths`), `ExprParser.kt` (formulas), `TableChart.kt`, `Picture.kt`; drawing of charts is `ChartDraw.kt`; the chart and table windows are `ChartDialog.kt` and `TableDialog.kt`.

- **Ink format** (`proto/ink.proto`, `core/internal/ink`, generated `inkpb` via `make proto`, which needs `protoc` and `protoc-gen-go` v1.36.10 in `~/go/bin`; run it with `PATH=$PATH:$HOME/go/bin`): a header plus events; field numbers never change, readers skip what they do not know. Kotlin builds its own lite classes from the same file; `proto/testdata/sample.stylog` is shared by the Go and Kotlin tests. Only the Go side reads and dumps logs (`styli ink dump`).
- Settings (penmanship, scrolling, outline style, ruler units and so on) and colour pickers are throwaway menu items and are not saved.
- A lasso move can cross to another page (copy then delete, two undo steps); an eraser drag or text box cannot; drawing undo is per page and page changes (move, swap, delete) have their own undo; a deleted table row or column deletes the ink in it (one undo step brings it back).
- Fills are static colour; connectors attach to shapes only; right-angle routes do not avoid other shapes; a column of pages can have gaps. The dotted pen is drawn by the page layer (a little delay, no pressure). Stroke bounds for culling come from the points plus the brush size, not the rendered edge. The lasso selects whole strokes only. The zoom-out limit is 35% of the whole-surface fit; below 90% scroll is free.
- Pictures and charts are ignored by the erasers; a chart that cannot be drawn is skipped and logged under the tag `Chart`.

## How to test on the tablet

- Build and install: in `android/`, `./gradlew assembleDebug testDebugUnitTest` (about 20 s warm; a long first build can hit the 2-minute tool limit, run it again); `adb -s <ip:port> install -r app/build/outputs/apk/debug/app-debug.apk`; `adb -s <ip:port> shell am force-stop app.styli.ink`; launch with `adb -s <ip:port> shell monkey -p app.styli.ink -c android.intent.category.LAUNCHER 1`. The tablet shows twice in `adb devices` (an IP and a `_adb-tls-connect` name): always pass `-s <ip:port>` (it was `192.168.2.135:35229`). Wireless adb must be reconnected after a reboot. Go ink tests: `cd core && go test ./internal/ink ./cmd/...`.
- `adb shell input stylus tap X Y` gives pen events, `input tap` works for the Compose buttons and dialogs, `input swipe` is a finger swipe (slow ones test scrolling and pulls; a swipe from the right edge pages through the chart samples), `adb exec-out screencap -p > .playwright-mcp/x.png` plus the Read tool to look; delete the files afterwards. The screen is 1200 by 2000; the top toolbar scrolls sideways (`input swipe 1000 93 300 93`).
- A temporary hook (a debug function called from an intent extra in `MainActivity`) is a quick way to put a chart or table on screen and screenshot it; remove it afterwards. `adb logcat -d -s Chart AndroidRuntime` shows drawing errors; `Log.d("DBG", ...)` plus `adb logcat -d -s DBG` shows what a gesture did.
- `adb shell input stylus swipe` is unreliable for judging ink (late, bursty, pressure 1.0); judge ink with the user's own pen.

## Ink library lessons (androidx.ink 1.1.0-alpha12)

- `CanvasStrokeRenderer.draw(canvas, stroke, matrix)` does **not** apply the matrix: also `canvas.concat(matrix)`, or finished strokes draw at page-unit coordinates (invisible ink).
- `InProgressStrokesView.startStroke(..., motionEventToWorld, strokeToWorld)` takes the screen-to-page matrix; the live layer draws in screen pixels, so no pan or zoom during a stroke.
- On the SM-P620 a finished stroke was not drawn until the next touch. Fixed by `liveLayer.requestHandoff()` (experimental, `ExperimentalInkHandoffApi`) plus 30 frames of `postOnAnimation` invalidation after pen-up (`keepDrawing`); the real cause was never found. If strokes vanish or lag again, start there.
- The library hands strokes off in groups ("cohorts"), so several quick strokes arrive in one callback.

**Known limits worth remembering**
- Recovery candidates show only on the atrium; a stale-delete candidate copies the atrium's version (a large attached file takes the space twice until reviewed); a candidate restore that fails after the note left the trash can be repeated.
- Sync: resuming trusts only the final hash check (a damaged part wastes a pass); unfinished parts stay 24 hours; a delete and a restore at once end in a trash or a candidate, never lost; status errors on a device's Settings card are Go error text; a merge needing a name another note holds waits; bases marked deleted stay a few hundred bytes each; tests crash device writes, not the atrium.
- HTTPS and sign-in: the CA download page warns once (the fingerprint check is the protection); `styli-<id>.local` resolves only while the atrium announces itself, otherwise use `--web-name`; on the atrium's own machine use `https://localhost:<port>`; the first sign-in link is printed to the log (30 minutes); the join limit is global; a device's own `styli serve` page has no sign-in.
- Version check compares only the protocol number (an atrium at protocol 2 must still serve devices at 1; nothing checks that yet), and `join` does not check it. Discovery: no way to change a device's saved addresses after pairing; Android needs a `MulticastLock`; VPNs rarely carry multicast. `styli join` refuses an already paired device. `join` recognises "no pairing open" by Go's TLS error text.
