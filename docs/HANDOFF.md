## Saving to disk (how it works; the format is in DESIGN.md)

- Notes are plain files in `Documents/Tabularium` (needs the "all files" permission, asked on first start; `adb shell appops set app.styli.ink MANAGE_EXTERNAL_STORAGE allow` grants it for testing). The folder is chosen at the first start and in Settings, Storage; the choice is in the app's preferences (`Storage.kt`); Android's picker will not give the top of storage, and only phone and SD card storage work. A move copies and never deletes the old folder; a folder that already has files is only opened, never merged.
- `Vault.kt` makes the disk match the `Library` (create, rename, move, trash, append events); autosave about a second after a change, and on leaving the app (ON_STOP, so pressing Home saves; force-stop does not). `InkLog.kt` is the writer and reader (every object kind); a cut last record is ignored, a damaged or header-less file is refused and left alone. `MiniJson.kt` writes the small files. Per note: `file.json`, `view.json` (tool, zoom, scroll, pens), `page-NNN.stylog`, `pictures/`, `.deleted/`. App-wide in `.styli/`: `seq`, `settings.json`, `clips/` (the clip shelf, shared by all notes).
- Every event is written by the device named `george` until pairing exists. Rounding: the format is whole 0.01 mm units, so floats are rounded on save.
- **Not saved:** undo history (the user decided it is not needed; version history covers it), current zoom of the library, edits made to the files outside the app while it runs (no watching; it would overwrite them). Pictures: bytes live in `Notebook.pictureFiles`; covers do not show pictures (one-page notebook has no store).
- Tests: `InkLogTest`, `VaultTest` (temp folders), plus the older model tests. Dump a saved page with `cd core && go run ./cmd/styli ink dump FILE`.

## Phase 3 code map

Kotlin in `android/app/src/main/kotlin/app/styli/ink/`, tests in `android/app/src/test/kotlin/app/styli/ink/`. `PageModel` (plain Kotlin) is one page with undo steps, a `log` of events not yet saved, and a `revision` counter; `Notebook` holds the pages, page undo and picture bytes; `InkCanvasView` does touch, drawing and the lasso (3,300+ lines; `snapshot` for covers, `viewState`/`startView` for scroll and zoom); `MainActivity` has `Root` (permission, folder choice, vault, autosave, note open animation) and the throwaway toolbar `InkScreen`. `Library`/`LibUi`/`LibraryScreen`/`FolderPanel`/`TrashScreen`/`SettingsScreen`/`AppSettings`/`NoteView` are the Tabularium side. Pure maths is in small JVM-tested files (`PageGeometry`, `NotebookLayout`, `LassoGeometry`, `Chart.kt`, `ExprParser.kt`, `TableChart.kt`, `Picture.kt`); chart drawing is `ChartDraw.kt`.

- **Ink format** (`proto/ink.proto`, `core/internal/ink`, generated `inkpb` via `make proto`, needs `protoc` and `protoc-gen-go` v1.36.10 in `~/go/bin`; run with `PATH=$PATH:$HOME/go/bin`): header plus events; field numbers never change; readers skip unknown kinds. Kotlin builds lite classes from the same file; `proto/testdata/sample.stylog` is shared by the Go and Kotlin tests.
- A lasso move can cross to another page (copy then delete, two undo steps); an eraser drag or text box cannot; drawing undo is per page and page changes have their own undo. Fills are static colour; connectors attach to shapes only; right-angle routes do not avoid shapes; the dotted pen is drawn by the page layer. The lasso selects whole strokes only. Zoom-out limit is 35%; below 90% scroll is free. Pictures and charts are ignored by the erasers; a chart that cannot be drawn is skipped and logged under tag `Chart`. An infinite-canvas note shows one page only, so pages added by Chart samples are hidden there.

## How to test on the tablet

- Build and install: in `android/`, `./gradlew assembleDebug testDebugUnitTest` (about 20 s warm; a long first build can hit the 2-minute limit, run again); `adb install -r app/build/outputs/apk/debug/app-debug.apk`; `adb shell am force-stop app.styli.ink`; launch with `adb shell monkey -p app.styli.ink -c android.intent.category.LAUNCHER 1`. adb is at `~/Android/Sdk/platform-tools`. The tablet (SM-P620, Android 16, wireless adb; it shows as `adb-R52X8045NAW-...._adb-tls-connect._tcp`) was the only device, so no `-s` was needed in the last session; if two entries show, pass `-s`. Reconnect wireless adb after a reboot.
- `input tap X Y` for Compose buttons; `input swipe` is a finger swipe (scrolls; slow ones count as pulls); `input stylus swipe x1 y1 x2 y2 ms` drew straight pen lines that saved correctly (judge handwriting feel with the user's own pen); `adb shell input draganddrop X1 Y1 X2 Y2 MS` drives a hold-and-drag (run it in the background and screenshot mid-drag); `adb exec-out screencap -p` plus the Read tool to look (screen 1200 by 2000; the top toolbar scrolls sideways, `input swipe 1000 93 300 93`). Screenshots go in the scratchpad, never the repo.
- `adb logcat -d -s AndroidRuntime:E` after a launch shows crashes; `Log.d("DBG", ...)` plus `-s DBG` shows what a gesture did; look at saved files with `adb shell find /sdcard/Documents/Tabularium` and `adb exec-out cat FILE`.
- A rare failure: tapping a card position after a layout change opens another note (the Recent list reorders by last opened), so screenshot before tapping.

## Ink library lessons (androidx.ink 1.1.0-alpha12)

- `CanvasStrokeRenderer.draw(canvas, stroke, matrix)` does **not** apply the matrix: also `canvas.concat(matrix)`.
- `InProgressStrokesView.startStroke(..., motionEventToWorld, strokeToWorld)` takes the screen-to-page matrix; the live layer draws in screen pixels, so no pan or zoom during a stroke.
- On the SM-P620 a finished stroke was not drawn until the next touch. Fixed by `liveLayer.requestHandoff()` plus 30 frames of `postOnAnimation` invalidation after pen-up (`keepDrawing`); the real cause was never found.
- Strokes arrive in groups ("cohorts"). A stroke made of too few points draws as separate dabs (my sample strokes did); real pen input is dense.

Two-machine check closed 2026-11-25. Every sync, merge, delete, TLS, pairing or login step from now on: plan first, wait for approval, Opus where the build plan says.

**Known limits:** recovery candidates show only on the atrium; sync resuming trusts only the final hash check; version check compares only the protocol number; no way to change a device's saved addresses after pairing; Android needs a `MulticastLock` and VPNs rarely carry multicast; the first sign-in link is printed to the log; README still says "hub" in places (the user wants the GitHub version kept).

**Run and test (Go):** `make build`, `./out/styli serve --vault DIR` (web `127.0.0.1:7878`, sync `:7879`); `styli join --vault DIR --atrium HOST` on the second machine. `make test` (about 15 s). Sync alone: `cd core && go test ./internal/syncdev` (`-short`, `-race`, `-run 'TestRandomised/seed_7'`); after changing sync code loop `for i in $(seq 1 25); do go test ./internal/syncdev -run TestRandomised -count=1 || break; done`. LAN checks (iPhone, second machine) need `ufw` rules opened by the user in their own terminal; details in the memory note `lan-test-setup`. Names: the hub is the **atrium**, the vault the **tabularium**, the graph the **Nexus**, paths are **Itineraria**; on-disk and API names still say `hub`.
